# Changelog

`VERSION` is the single source of truth: every version in shipped metadata (plugin and marketplace manifests, `SKILL.md`, each reference, each agent, each registry) equals it exactly. A PR that changes shipped content raises `VERSION`, moves every version with it, and adds a `## X.Y.Z — date` section here. `scripts/check_version_sync.py` and `tests/sc-plan-anchor/test_version_ssot.py` enforce it (see CONTRIBUTING.md).

## 0.7.3 — 2026-10-17

- **Breaking for anyone setting these variables.** `TYPESAFE_API_KEY` is now the plugin's only environment variable (ANC-005, REQ-018). `jev_judge.py` no longer reads `PLAN_ANCHOR_JEV_MODEL`, `PLAN_ANCHOR_CONFIDENCE_THRESHOLD`, `PLAN_ANCHOR_MAX_ITEM_CHARS`, `PLAN_ANCHOR_MAX_CODE_LINES`, `PLAN_ANCHOR_CONFIRM_NEAR` or `PLAN_ANCHOR_JEV_URL`; setting them has no effect. The defaults (`jev-latest`, 0.6, 24,000, 8, confirmation on) are checked-in constants; use `--model`, `--threshold`, `--max-item-chars`, `--max-code-lines` and `--no-confirm` instead. The endpoint has no override: tests redirect it by patching `jev_judge.JEV_URL` in-process. A non-numeric value is now a flag usage error (`VALIDATION.INPUT`, exit 2) instead of a module-load error, and `parse_env_number` / `_env_number` are gone. `--stated-by` still defaults to the OS `USER`. The variables are removed from jev-api (environment table, endpoint, model pinning, confirmation), verdict-gating and installation-and-troubleshooting (template and render), and from `jev_judge.py`'s help and error actions. Tests plant each old variable with a wild value and assert the dry-run output, the live request, its URL and the verdict are unchanged, and scan the shipped tree for any `PLAN_ANCHOR_` string and for any environment read other than `TYPESAFE_API_KEY` and `USER`.
- Example ids are tracker-neutral: `bd-42`, `bd-41` and `bd-10`–`bd-12` become `ex-42`, `ex-41` and `ex-10`–`ex-12` in plan-anchor-questions, report-format, verdict-gating, jev-api, anchor-document, bead-layout, `anchors.example.json` and the tests. The single-tracker installer test now runs over every installed file (not only `.md`) and counts `bd-42`-style ids as a mention; its allow-list is the install guide (it explains both trackers) and `scripts/*.py` (code that supports both), each with its reason.

## 0.7.2 — 2026-10-17

- **Breaking for anyone scripting on exit 1.** Every plan-anchor CLI now follows one convention: a tool failure returns an error in the exit code; a call that ran properly and returned a negative result still ran properly. Exit 0 means the command ran (`{"success": true, "data": {...}, "error": null}`) and `data` carries the outcome, negative ones included. Exit 2 means it could not do its job (`{"success": false, "data": null, "error": {code, message, recoverable, suggested_action}}`): bad arguments, a missing or unreadable file, invalid settings, `POLICY.REMOTE_JUDGE_DISABLED`, an auth or network failure that stops the run, a missing dependency, `SCRIPT.INTERNAL`. Exit 130 stays for interrupts. No command exits 1 any more. Read the outcome field, not the exit code.
- `jev_judge.py` outcome fields: `judge` `data.summary.pass` (a failing or `error` verdict was exit 1, now exit 0 with `pass: false`); `check-fixtures` `data.pass` and `data.mismatches` (mismatch was exit 1); `validate` new `data.valid` with `data.problems` (problems were exit 1 with `success: false`, now `success: true`, `valid: false`); `lint` new `data.clean` (warnings were exit 1); `rubric` `data.pass` (`needs_work` was exit 1); `dedupe` `data.likely_duplicates` (duplicates were exit 1). The `add` quality-gate refusals (`ANCHOR.LINT` under `--strict`, `ANCHOR.DUPLICATE_CANDIDATE`, `ANCHOR.NOT_TESTABLE` under `--rubric`) and `update --strict` were exit 2 errors and are now exit 0 with new `data.added` / `data.updated` false and `data.refused {code, message, suggested_action}`; nothing is written. The verbatim-quote rule on `update` stays a `VALIDATION.INPUT` error.
- `anchor_runner_contract.py validate-fence` and `anchor_tuning_contract.py`: a request or result that was read and checked exits 0 with `data.valid` true (runner: plus `data.value`) or false with `data.violation {code, message}`; contract violations were exit 2. An unreadable file, bad arguments, a missing `--correlation-id` for a result, and `SCRIPT.INTERNAL` stay exit 2. `anchor_tracker.py`, `plan_anchor_settings.py` and `install.py` already used 0/2 and are unchanged.
- Repository scripts: `scripts/check_version_sync.py` drift and `scripts/gen_install_data.py --check` staleness exit 2 (were 1). Their job is to fail CI, so they stay nonzero, sharing exit 2 with errors; the message says which. `scripts/install_sc_compose_ci.py` failures exit 2.
- Callers read the JSON: the gate agents, the skill's Step 1, and the references (jev-api, verdict-gating, planning-gate, development-gate, triage-and-iteration, anchor-document, anchor-capture, capture-and-maintenance-workflow, agent-runner-contract, question-tuning-workflow, installation-and-troubleshooting, reference-catalog), the agent-invocation template and the README describe exit 0 with the outcome field. A test fails if a shipped prompt or reference mentions exit 1.

## 0.7.1 — 2026-10-17

- Replace the per-session remote-judge opt-in with a committed repository answer. `.sc/plan-anchor/settings.yaml` gains `allow_remote_judge: true|false` (a bool; the schema stays strict and `schema_version` stays 1). `true` lets live Jev calls through; `false` refuses them with `POLICY.REMOTE_JUDGE_DISABLED`; an absent answer refuses with the same code and an action that says to ask the user once, record the answer with `python3 scripts/plan_anchor_settings.py set allow_remote_judge true|false`, and commit the file. A non-bool value is `SETTINGS.INVALID_REMOTE_JUDGE`. `jev_judge.py` stays standard-library only and imports the settings module lazily, for live calls only; a present settings file without PyYAML is `DEPENDENCY.PYYAML` (exit 2), never a silent default. `--dry-run` and `--answers-file` need no answer. The live subcommands (`judge`, `check-fixtures`, `dedupe --jev`, `rubric`, `add --rubric`) take `--repository-root` (default `.`), found with the same lookup as `anchor_tracker.py`.
- Remove `PLAN_ANCHOR_ALLOW_REMOTE_JUDGE` and `--allow-remote` from every subcommand, the skill's Step 1, the agents, the references (jev-api, installation-and-troubleshooting, verdict-gating, planning-gate, triage-and-iteration, reference-catalog), the templates and the README. Setting the variable has no effect and `--allow-remote` is a `VALIDATION.INPUT` usage error. This removes existing names in a patch release, against CONTRIBUTING's add-only rule, by operator decision: an autonomous run must not be asked for consent every session. Agents never write `allow_remote_judge` and return `POLICY.REMOTE_JUDGE_DISABLED` unchanged; the skill asks once when the answer is absent and never infers consent from existing run files or past runs.
- New `scripts/plan_anchor_settings.py show` and `set allow_remote_judge true|false`, which keep the other keys, refuse to overwrite a malformed file, and report the paths to commit. `anchor_tracker.py write` keeps the answer. The installer takes `--allow-remote-judge` / `--no-remote-judge`; a rerun without either keeps the recorded value. This repository records `allow_remote_judge: true`.
- Argparse usage errors in `jev_judge.py`, `anchor_runner_contract.py` and `anchor_tuning_contract.py` are `VALIDATION.INPUT` envelopes on stdout with exit 2 instead of argparse text, and `anchor_runner_contract.py` maps an unexpected exception to `SCRIPT.INTERNAL` like the other scripts. `jev_judge.py validate` still exits 1 on problems.
- The committed (neutral) render no longer falls back to bd: SKILL.md, development-review-workflow, report-format, plan-size-and-shape, reference-catalog and bead-layout show `"$ANCHOR_TRACKER"` or both trackers' commands. The br and bd renders are unchanged.

## 0.7.0 — 2026-10-17

- Add `plugins/sc-plan-anchor/install.py`, which vendors the skill and agents into a repository: `uv run plugins/sc-plan-anchor/install.py --dest <repo> [--tracker br|bd] [--target claude,codex,cursor] [--init-br] [--overwrite] [--dry-run]`. Inline script metadata (PEP 723) supplies PyYAML and the `sc-compose` wheel, so no pip step is needed; the header pins CPython 3.11 because sc-compose 1.7.0 publishes 3.11 wheels only, and the code itself runs on 3.9+. Installed text names one tracker: tracker-specific skill references and agent bodies are strict sc-compose templates in `install/templates/` rendered for `br` or `bd`, and the committed plugin tree is their `neutral` render (tests pin committed == neutral and that a br install has no bd command or wording and vice versa). Both gate agents render the selected tracker.
- The installer records version, tracker, targets and every file's sha256 in `<repo>/.sc/plan-anchor/install-lock.json`, the only state it keeps. Reruns replace only unchanged owned files, remove files this version no longer ships (for example `anchor-question-tune.md` and the skill's old `tests/`), refuse with `INSTALL.CONFLICT` naming a modified or foreign file unless `--overwrite` moves it to `<repo>/.backup/<UTC>/`, and never write over unowned files; every check runs before any write. A pre-lock install migrates once by matching bytes against every earlier release (`install/legacy-owned.json`, generated from git history by `scripts/gen_install_data.py`, as is `install/manifest.json`).
- Tracker choice reuses `anchor_tracker.py`'s rules (`--tracker`, else `anchor_tracker` in `.sc/plan-anchor/settings.yaml`, else detection) and writes the setting. bd requires a Dolt-backed `.beads/`; with no `.beads/` the install fails with `TRACKER.NOT_INITIALIZED` unless `--init-br` runs `br init`. `bd init` is never run or recommended. Rerunning with the other `--tracker` re-renders every installed target and updates the setting; it does not migrate issue data. Rewrite `references/installation-and-troubleshooting.md` around the installer and update the README install section (reference-catalog, installation-and-troubleshooting).
- Both gates judge the sprint text the caller already wrote (ADR-014, REQ-057; supersedes ADR-005's plan-source normalization). `anchor-plan-review` and `anchor-sprint-review` take `item_id`, `item_title` and `item_file`, the Markdown sprint file, the bead as the selected tracker shows it (`"$ANCHOR_TRACKER" show <id> --json` with `compose-item`), or text from the caller's context, in any layout, and pass it to `jev_judge.py judge --item-file` unchanged; descriptor mode, `item_path` and the legacy `bead_id`/`sprint_id` inputs are removed. The development gate now resolves its tracker with `anchor_tracker.py resolve` like the planning gate and reads question beads with it, replacing the 0.6.1 scope (planning gate only). `jev_judge.py` keeps its size cap and `PLAN.TOO_LARGE`; `lint --plan-items` accepts bd/br `show --json` output or a JSON list of ids, no longer `discover` output. `scripts/plan_source.py` and `references/plan-source-contract.md` are no longer shipped; an upgrade removes them.
- Indented template branches keep their indentation and nested frontmatter renders cleanly; CI adds an `installer` job (CPython 3.11, Linux and macOS) that installs the wheel and fails instead of skipping the rendering tests.

## 0.4.0 — 2026-10-10

- Split harness adapters: Claude Code gate agents use Sonnet and its independent question tuner uses Opus; Codex gate agents use Luna and its tuner uses Sol. Claude invocation now names the Agent tool, and both registries are version-checked.
- Made question tuning independent of the planner. The tuner derives and freezes an oracle from approved intent and anchors before its first Jev call, iterates wording against role-level expectations without a plan-pass objective, and returns the oracle digest, rationales, run IDs, and acceptance table.
- Added `agent-preflight` to canonicalize and confine agent inputs to the Git workspace, reject unsafe identifiers and PR numbers, and require the running judge to match the selected script. Agents validate harness-controlled script paths before execution.
- Redact the live TypeSafe key and bearer credentials recursively from all script output. Installation reads the key silently instead of placing it in a command line.
- `diff` now reports composed-item growth. Remediation defaults to cuts and replacements; a failing-to-passing edit may grow only when added text traces to a locked ANC/REQ/ADR that predates the failed run.
- Documentation consistently treats Jev as required for the normal capture, tuning, fixture, and gate workflow while preserving offline dry-run and fixture-answer support for development and CI. Examples now use measured, non-placeholder metadata.
- Planning gate sends a bead whole when it fits one Jev request (`--max-item-chars`, and `--max-request-bytes` for every anchor). Otherwise blocks longer than `--max-code-lines` are reduced to signatures one at a time, longest first, until it fits. `PLAN.TOO_LARGE` is unchanged. Measured on a 13-bead plan with 6 anchors: underspecified cells went from 15 to 8, and passing beads from 1 to 6 (`docs/experiments/2026-10-10-redact-only-when-oversize.md`).
- Planning gate is a quality loop: Jev's failing verdicts and low confidence are the planner's signal to fix the bead, then re-run. `underspecified` results carry `low_questions`, printed as `Low:` report lines. `anchor-plan-review` returns Jev's ruling unchanged plus `to_fix` per failing cell, resolves overrides deterministically, and can reuse a run after one timed-out or malformed agent response without another Jev call.
- Fixed directive gating so a low-confidence, `unclear`, or otherwise non-confident `no` conflict answer is `underspecified`; only a confident conflict `no` can reach `asserted_only` or `satisfied`.

## 0.3.0 — 2026-10-10

Shaped by first use on a real multi-sprint plan and 245 live Jev requests against it (`docs/experiments/2026-10-10-phase-h-jev-experiments.md`).

- Anchors: `statement` is a testable requirement; the user's exact words are a separate immutable `quote`. `add` refuses a statement equal to its quote and near-duplicates (`ANCHOR.DUPLICATE_CANDIDATE`); `update --statement` rewords with history; `retire` replaces hand edits.
- Anchor `kind`: `directive`, `prohibition` (judged on contradiction only), `structural` (deterministic check only, verdict `deterministic_only`).
- New subcommands: `lint` (testability rules), `rubric` (Jev-judged testability, six criteria), `dedupe` (lexical, optionally Jev), `shape` (per-bead size, code/prose, references, repeated paragraphs), `compose-item --for plan|dev`, `diff --expected`.
- Planning gate judges title, description and acceptance criteria; never shortens prose; long code goes to Jev as signatures; an oversized bead is `PLAN.TOO_LARGE` and triaged as a symptom (unapproved work, prose and ceremony, split last).
- Gate caps: plan 24,000 bytes (what Jev reads reliably), dev 64,000. Near-threshold cells are re-asked once; every result carries `leaning`.
- New agent `anchor-question-tune` (background): proves and refines per-anchor question wording against fixtures and known beads.
- New references: `planning-gate`, `development-gate`, `question-tuning`, `triage-and-iteration`, `plan-size-and-shape`, `measured-behaviour`.
- 134 offline tests; CI on Linux, macOS, Windows.

# Changelog

`VERSION` is the single source of truth: every version in shipped metadata (plugin and marketplace manifests, `SKILL.md`, each reference, each agent, each registry) equals it exactly. A PR that changes shipped content raises `VERSION`, moves every version with it, and adds a `## X.Y.Z — date` section here. `scripts/check_version_sync.py` and `tests/sc-plan-anchor/test_version_ssot.py` enforce it (see CONTRIBUTING.md).

## 0.8.4 — 2026-10-19

- The installer docstring and skill text describe what the installer reads and writes. Both said everything the installer reads is inside the plugin directory; `install.py` also reads, at and above the destination, `.sc/plan-anchor/settings.yaml` (the destination's own, else the nearest above for `anchor_tracker`), the install lock, `.beads/` (the tracker / Dolt check), whether `.git` exists (git is never run) and the files already at the install paths, plus the home directory (to refuse global destinations and end the upward walks) and `PATH` (to find the tracker CLI). The docstring now also lists `.backup/<UTC>/` and `.backup/.gitignore` among the writes, states that sc-compose and PyYAML run in-process and `br init` (with `--init-br`) is the only external command, that a rerun keeps the locked targets, that the SessionStart hook is Claude Code only, and the exit codes (0 with negative results in `data`, 2 with a typed envelope, 130 on interrupt). The installer skill states the same briefly, reads the tracker from the nearest settings file above the folder when the folder's own sets none, keeps only the folder's own remote-judge answer, and says not to install on `newer`. REQ-067 and ADR-015 list the same reads. No behaviour change.

## 0.8.3 — 2026-10-18

- **Breaking for anyone reading Jev failures from exit 0.** A Jev call that got no answer is now a tool failure, never a negative result. `judge`, `check-fixtures`, `dedupe --jev`, `rubric` and `add --rubric` exit 2 with the typed envelope when any cell, pair or candidate still has no answer after the retries (transport and HTTP errors, `JEV.RESPONSE_INVALID`, `JEV.CONTEXT_EXCEEDED`, a per-cell `PLAN.TOO_LARGE`, a failed near-threshold confirmation, or `FIXTURE.MISSING` and malformed entries in an answers file). `error.code` is the first failure's code and `error.message` counts them ("1 of 2 judged cells got no answer from Jev: ..."). The partial work is still written and returned in `data`: `judge` returns the run as written (`data.run_path`, `results`, `summary`), `check-fixtures` its runs, `dedupe` its pairs, `rubric` its entries, and every case adds `data.failures` (`{id, code, message}` per item without an answer). Before, `judge` exited 0 with `verdict: error` cells, `dedupe` reported `likely_duplicates: []` beside unanswered pairs, `rubric` reported them as `needs_work`, and `add --rubric` turned a failed rubric into `ANCHOR.NOT_TESTABLE`, so `--allow-untestable` recorded the anchor anyway; now nothing is recorded, with or without the flag. A dry run asks Jev nothing and still exits 0. An answers file that is not an object stays exit 2.
- Refusals and no-ops exit 0. `add` of an ID already recorded (`ANCHOR.DUPLICATE`) and a statement that repeats the quote (`VALIDATION.INPUT`, on `add` and `update`) are refusals in `data.refused`, like the lint, duplicate-candidate and rubric refusals; every `data.refused` now carries `recoverable` again (`{code, message, recoverable, suggested_action}`). An `update` with nothing to change, `retire` of a retired anchor and `exclude --remove` with no exclusion to remove exit 0 with `data.changed: false` and write nothing (they were `VALIDATION.INPUT`). A real `update` keeps `data.changed` as the list of changed fields; `retire` and `exclude` report `changed: true`.
- `check-fixtures` with nothing judged (every selected check `deterministic_only`, i.e. structural anchors at the plan gate) reports `pass: false`, `judged: 0` and a `note`, instead of `pass: true`: no fixture was tested, so the command cannot say the fixtures pass. `data.judged` is new on every run.
- Run files are redacted: `save_json` applies the same redaction as stdout, so the `TYPESAFE_API_KEY` value and bearer tokens never reach a run file (or `anchors.json`), whatever input carried them (REQ-017).
- Every CLI (`jev_judge.py`, `anchor_tracker.py`, `plan_anchor_settings.py`, `anchor_runner_contract.py`, `anchor_tuning_contract.py`, `install.py`) prints a `CANCELED` envelope (`recoverable: true`, `canceled: true`, `aborted_by: "user"`) and exits 130 on interrupt (new `result.run_main`). Only `jev_judge.py` did before; the others printed a traceback.
- Settings inside a repository: the nearest `.sc/plan-anchor/settings.yaml` walking up from the working directory wins, even below the repository root (it was looked up from the git top level). `plan_anchor_settings.py show`/`set`, `anchor_tracker.py resolve`/`write` and `jev_judge.py`'s consent check all use it, so an install in `<repo>/sub` reads and writes `<repo>/sub/.sc/plan-anchor/settings.yaml` from there. `install.py --dest <repo>/sub` without `--tracker` takes the tracker from the nearest settings file above it or the enclosing repository's `.beads/` (and `--init-br` runs at the repository root) instead of failing with `TRACKER.REQUIRED`; the child settings file does not copy the parent's consent.
- Trust rule: `agent-preflight` and both gate agents now accept a `jev_judge.py` only when the install root's `.sc/plan-anchor/install-lock.json` lists it, so a hand-copied or lock-less copy is `VALIDATION.PATH`. `.agents/` is no longer a trusted harness directory (it stays a refused global location under the home directory); whether Codex installs should move to `.agents/skills` is still open.
- CI scripts exit 2 with a message, never a traceback: `check_version_sync.py --base <ref>` with a ref that does not exist, an unreadable, malformed or non-object manifest or catalog; `gen_install_data.py` when a git command fails or `legacy-owned.json` is unreadable, corrupt or not an ownership record; `install_sc_compose_ci.py` on any unexpected exception.
- Prompts: the gate agents' result envelopes drop `exit_code`. The overrides loop reports a question bead the tracker cannot show as `TRACKER.SHOW_FAILED` instead of silently judging with default questions. The planning gate no longer says a dry run passes, and lists `asserted_only` among the failing verdicts. The agents, jev-api, development-gate, planning-gate, verdict-gating and the install guide describe the rules above.
- Test changes. Existing tests that asserted the old behaviour now assert the new rule: `test_jev_judge.py` `AddTests.test_register_anchors_keep_their_id_and_refuse_duplicates`, `QuoteTests.test_statement_equal_to_quote_is_refused`, `KindTests.test_add_update_validate_kind`, `RetireUpdateTests.test_retire`, `test_update_fields_and_fixtures`, `test_update_statement_is_allowed_and_recorded`, `DedupeTests.test_jev_pass_with_answers_file_dry_run_and_opt_in`, `test_jev_live_uses_the_transport_policy`, `RubricTests.test_record_form_with_answers_file`, `test_live_candidate_uses_the_transport`, `ConfirmTests.test_fixture_answers_are_never_rejudged_and_a_failed_rejudge_keeps_the_first`, `JudgeFixtureTests.test_missing_fixture_entry_is_an_error_verdict`, `test_malformed_fixture_answer_is_response_invalid`, the `TransportPolicyTests` error cases and `PlanSizeTests.test_plan_gate_context_overflow_is_too_large_not_halved`; `test_jev_judge_exclude.py::ExcludeCommandTests.test_exclude_refuses_bad_input` (the `--remove` case); `test_error_contracts.py` (`anchor_duplicate` and `verbatim_statement` move to the refusal cases, every refusal pins `recoverable`, `fixture_missing` exits 2 and its test becomes `test_fixture_missing_is_a_tool_failure_with_the_partial_run`, and the transport cases exit 2); `test_windows_portability.py::NoHomeDirectoryTests.test_settings_lock_and_install_lookups_do_not_raise` (its lock lists the script); `test_exit_convention.py` asserts `AUTH.CREDENTIALS` for the keyless `judge` case. `layout_support.installed_scripts` writes an install lock (`lock=False` for a hand copy). New `test_jev_failures.py` (each Jev-failure path through a real process, a closed port 127.0.0.1:9 and missing or malformed fixtures; refusals and no-ops; run-file redaction with a canary key; exit 130 from each CLI on POSIX), `test_ci_scripts_exit.py` and `test_subfolder_and_trust.py`, and `test_exit_convention.py::JevJudgeErrors.test_live_judge_refusals_are_typed`.

## 0.7.2 — 2026-10-17

- **Breaking for anyone scripting on exit 1.** Every plan-anchor CLI now follows one convention: a tool failure returns an error in the exit code; a call that ran properly and returned a negative result still ran properly. Exit 0 means the command ran (`{"success": true, "data": {...}, "error": null}`) and `data` carries the outcome, negative ones included. Exit 2 means it could not do its job (`{"success": false, "data": null, "error": {code, message, recoverable, suggested_action}}`): bad arguments, a missing or unreadable file, invalid settings, `POLICY.REMOTE_JUDGE_DISABLED`, an auth or network failure that stops the run, a missing dependency, `SCRIPT.INTERNAL`. Exit 130 stays for interrupts. No command exits 1 any more. Read the outcome field, not the exit code.
- `jev_judge.py` outcome fields: `judge` `data.summary.pass` (a failing or `error` verdict was exit 1, now exit 0 with `pass: false`); `check-fixtures` `data.pass` and `data.mismatches` (mismatch was exit 1); `validate` new `data.valid` with `data.problems` (problems were exit 1 with `success: false`, now `success: true`, `valid: false`); `lint` new `data.clean` (warnings were exit 1); `rubric` `data.pass` (`needs_work` was exit 1); `dedupe` `data.likely_duplicates` (duplicates were exit 1). The `add` quality-gate refusals (`ANCHOR.LINT` under `--strict`, `ANCHOR.DUPLICATE_CANDIDATE`, `ANCHOR.NOT_TESTABLE` under `--rubric`) and `update --strict` were exit 2 errors and are now exit 0 with new `data.added` / `data.updated` false and `data.refused {code, message, suggested_action}`; nothing is written. The verbatim-quote rule on `update` stays a `VALIDATION.INPUT` error.
- `anchor_runner_contract.py validate-fence` and `anchor_tuning_contract.py`: a request or result that was read and checked exits 0 with `data.valid` true (runner: plus `data.value`) or false with `data.violation {code, message}`; contract violations were exit 2. An unreadable file, bad arguments, a missing `--correlation-id` for a result, and `SCRIPT.INTERNAL` stay exit 2. `anchor_tracker.py`, `plan_anchor_settings.py` and `install.py` already used 0/2 and are unchanged.
- Repository scripts: `scripts/check_version_sync.py` drift and `scripts/gen_install_data.py --check` staleness exit 2 (were 1). Their job is to fail CI, so they stay nonzero, sharing exit 2 with errors; the message says which. `scripts/install_sc_compose_ci.py` failures exit 2.
- Callers read the JSON: the gate agents, the skill's Step 1, and the references (jev-api, verdict-gating, planning-gate, development-gate, triage-and-iteration, anchor-document, anchor-capture, capture-and-maintenance-workflow, agent-runner-contract, question-tuning-workflow, installation-and-troubleshooting, reference-catalog), the agent-invocation template and the README describe exit 0 with the outcome field. A test fails if a shipped prompt or reference mentions exit 1.
